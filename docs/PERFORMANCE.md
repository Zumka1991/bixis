# Производительность bixis-term

Локальные CPU-замеры без Wayland-сервера и дочерней оболочки:

```bash
make -C term bench
```

Сборка использует обычный `-O2`. Отрисовка: 3840×2160, масштаб 200%,
`monospace` 11 pt; в среде проверки ячейка 17×34 px, сетка 224×62.
Глифы прогреты. Проверка очереди использует неблокирующий pipe с частичными
записями, поэтому результат зависит и от размера pipe в системе.

Замеры 2026-11-05 в одной среде до и после исправлений:

| Нагрузка | До | После |
|---|---:|---:|
| Неизменившийся экран, одна проверка | 0,008 мс | 0,008 мс |
| Изменение одной ячейки | 0,159 мс | 0,013 мс |
| Полная смена текстовой сетки | 9,27 мс | 7,18 мс |
| Слив очереди 8 МиБ | 22,8 мс | 1,62 мс |
| Слив очереди 32 МиБ | 705 мс | 8,34 мс |

При изменении по одной ячейке в верхней и нижней строках damage занимает
два прямоугольника общей площадью 1156 px. Раньше объявлялся один прямоугольник
3840×2108 px, включая неизменённые строки между ними. Это сравнение области
damage, а не измерение фактического трафика GPU.

Парсер в этих нагрузках выдаёт около 110–130 МиБ/с. Числа зависят от процессора,
нагрузки системы, шрифта и содержимого. Это отдельные синтетические замеры,
не FPS и не полная задержка от PTY до монитора. GPU, direct scanout и расход
памяти композитора этим бенчмарком не измеряются.

Проверки корректности:

```bash
make -C term check
```

Помимо VT и ввода, тесты сравнивают пиксели частичного и полного кадра,
покрытие изменений прямоугольниками damage, возврат `A → B → A` через два
буфера, широкие символы, курсор и выступающие глифы. I/O-тесты проверяют
backpressure, смену clipboard во время передачи, отключение получателя,
освобождение крупных буферов и порядок данных при дописывании в очередь PTY.
