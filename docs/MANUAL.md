# Bixis — руководство

Bixis — минималистичная Wayland-оболочка. Сейчас в ней готов первый
компонент — терминал `bixis-term`. Композитор `bixis` в планах (см. [ROADMAP](../ROADMAP.md)).

## 1. Требования

- Linux с Wayland-композитором, который поддерживает `xdg-shell`
  (GNOME, KDE, Sway, Hyprland, labwc, river, FeatherDE и другие).
- Компилятор C11 (gcc или clang), `make`, `pkg-config`.
- Библиотеки: `wayland-client`, `wayland-protocols`, `xkbcommon`, `freetype2`, `fontconfig`.
- Хотя бы один моноширинный шрифт (по умолчанию берётся `monospace`).

X11 не поддерживается и не планируется.

## 2. Установка зависимостей

**Ubuntu / Debian**

```bash
sudo apt install build-essential pkgconf libwayland-dev libwayland-bin wayland-protocols libxkbcommon-dev libfreetype-dev libfontconfig-dev
```

На старых Debian/Ubuntu пакет `libfreetype-dev` называется `libfreetype6-dev`.

**Arch Linux**

```bash
sudo pacman -S --needed base-devel wayland wayland-protocols libxkbcommon freetype2 fontconfig
```

**Fedora**

```bash
sudo dnf install gcc make pkgconf-pkg-config wayland-devel wayland-protocols-devel libxkbcommon-devel freetype-devel fontconfig-devel
```

## 3. Сборка и установка

```bash
git clone https://github.com/Zumka1991/bixis.git
```

```bash
cd bixis
```

```bash
make
```

Готовый бинарник лежит в `term/build/bixis-term`. Его можно запустить сразу,
без установки:

```bash
./term/build/bixis-term
```

Установка в `/usr/local` (бинарник и ярлык `.desktop` для меню приложений):

```bash
sudo make install
```

Установить в другое место можно через `PREFIX`, например в домашний каталог без `sudo`:

```bash
make install PREFIX=$HOME/.local
```

Для сборщиков пакетов работает `DESTDIR`:

```bash
make install DESTDIR=/tmp/pkg PREFIX=/usr
```

## 4. Запуск

```bash
bixis-term
```

Терминал запускает оболочку из `$SHELL`. Если переменная не задана, берётся оболочка
из `/etc/passwd`, а если не найдена и она — `/bin/sh`.
Дочерним процессам выставляются `TERM=xterm-256color` и `COLORTERM=truecolor`.

Версия:

```bash
bixis-term --version
```

Окно закрывается, когда закрыта последняя вкладка: через `exit` в оболочке,
`Ctrl+Shift+W` или кнопку закрытия окна.

## 5. Горячие клавиши

Сочетания распознаются по латинскому символу клавиши, поэтому работают в любой раскладке.
Например, `Ctrl+Shift+T` срабатывает и в русской раскладке, и там же `Ctrl+C` посылает `^C`.

### Вкладки

| Клавиши | Действие |
|---|---|
| `Ctrl+Shift+T` | Новая вкладка (открывается справа от текущей) |
| `Ctrl+Shift+W` | Закрыть текущую вкладку |
| `Ctrl+Tab`, `Ctrl+PgDn` | Следующая вкладка |
| `Ctrl+Shift+Tab`, `Ctrl+PgUp` | Предыдущая вкладка |
| `Ctrl+Shift+1` … `Ctrl+Shift+9` | Перейти к вкладке по номеру |

Полоска вкладок появляется только при двух и более вкладках. По вкладке можно кликнуть.

### Буфер обмена

| Клавиши | Действие |
|---|---|
| `Ctrl+Shift+C` | Скопировать выделение |
| `Ctrl+Shift+V`, `Shift+Insert` | Вставить |

### Прокрутка

| Клавиши | Действие |
|---|---|
| `Shift+PgUp` / `Shift+PgDn` | На страницу вверх / вниз |
| `Shift+Home` / `Shift+End` | В начало / в конец скроллбэка |
| Колесо мыши | По 3 строки |

Любая клавиша, которая посылает текст, возвращает вид в самый низ.
В полноэкранных программах (less, man, vim) скроллбэка нет: колесо посылает
стрелки, а `Shift+PgUp` / `Shift+PgDn` передаются самой программе.

### Шрифт

| Клавиши | Действие |
|---|---|
| `Ctrl+=` / `Ctrl+-` | Крупнее / мельче |
| `Ctrl+0` | Размер по умолчанию |

## 6. Мышь и буфер обмена

- **Левая кнопка, протянуть** — выделить текст. Выделение сохраняется при прокрутке.
- **`Ctrl+Shift+C`** — скопировать выделенное в системный буфер обмена.
- **Средняя кнопка** — вставить из буфера обмена. Primary selection появится в v0.2.

При вставке включается bracketed paste, если программа его запросила (bash, zsh, vim).
Тогда многострочный текст не выполняется построчно.

## 7. Настройка

В v0.1 настройки задаются при сборке, в стиле suckless: правишь
[`term/config.h`](../term/config.h) и пересобираешь. Конфиг, который читается при запуске,
запланирован на v0.2.

```bash
make && sudo make install
```

Что можно поменять:

| Параметр | По умолчанию | Описание |
|---|---|---|
| `FONT` | `"monospace"` | Любой шаблон fontconfig: `"JetBrains Mono"`, `"Fira Code:style=Retina"` |
| `FONT_SIZE` | `11.0` | Размер в пунктах |
| `PADDING` | `6` | Отступ вокруг текста, в пикселях |
| `SCROLLBACK` | `5000` | Строк истории на вкладку |
| `WHEEL_LINES` | `3` | Строк на щелчок колеса |
| `DEFAULT_COLS`, `DEFAULT_ROWS` | `100`, `30` | Начальный размер, если его не задал композитор |
| `MAX_TABS` | `32` | Максимум вкладок |
| `COLOR_*` | тёмная тема | Цвета текста, фона, курсора, выделения, вкладок |
| `palette[16]` | — | 16 базовых цветов ANSI |
| `bindings[]` | см. раздел 5 | Горячие клавиши |

Пример бинда: открывать вкладку по `Alt+T`:

```c
{ ALT, XKB_KEY_t, ACT_TAB_NEW, 0 },
```

Модификаторы: `CTRL`, `SHIFT`, `ALT`, `SUPER`. Имена клавиш берутся из
`<xkbcommon/xkbcommon-keysyms.h>` (`XKB_KEY_...`), для букв — в нижнем регистре.
Доступные действия:
`ACT_TAB_NEW`, `ACT_TAB_CLOSE`, `ACT_TAB_NEXT`, `ACT_TAB_PREV`, `ACT_TAB_GOTO` (аргумент — номер с нуля),
`ACT_COPY`, `ACT_PASTE`, `ACT_SCROLL_PAGE` (±1), `ACT_SCROLL_TOP`, `ACT_SCROLL_BOTTOM`,
`ACT_FONT_SIZE` (±шаг, 0 — сброс).

## 8. Что поддерживается

- Эмуляция xterm-совместимого терминала: курсор, стирание, вставка и удаление
  символов и строк, области прокрутки, альтернативный экран (vim, less, htop),
  табуляторы, псевдографика DEC.
- Цвета: 16, 256 и truecolor (`38;2;r;g;b` и `38:2::r:g:b`). Атрибуты: жирный, курсив,
  подчёркивание, инверсия, зачёркивание, тусклый, невидимый.
- UTF-8, двойная ширина (CJK, многие эмодзи), запасные шрифты для отсутствующих символов.
- Форма курсора по запросу программ (блок, подчёркивание, черта).
  Когда окно не в фокусе, курсор рисуется контуром.
- Заголовок окна и вкладки из OSC 0/2, ответы на DA, DSR и запрос цвета фона (OSC 11).
- Bracketed paste, focus events (`\e[I` / `\e[O`).
- HiDPI на композиторах с `wl_compositor` v6 (`preferred_buffer_scale`).

Пока не поддерживается (см. [ROADMAP](../ROADMAP.md)): события мыши для приложений,
reflow при изменении ширины, комбинируемые символы, цветные эмодзи, OSC 52, primary selection.

## 9. Решение проблем

**`can't connect to a Wayland display`** — терминал запущен вне Wayland-сессии.
Проверь, что переменная `WAYLAND_DISPLAY` задана:

```bash
echo $WAYLAND_DISPLAY
```

**`can't load font 'monospace'`** — в системе нет моноширинного шрифта. Поставь любой,
например на Ubuntu:

```bash
sudo apt install fonts-dejavu-core
```

**Квадратики вместо символов** — ни в одном шрифте нет этого символа.
Для CJK поставь `fonts-noto-cjk`. Цветные эмодзи пока не рисуются.

**Нет рамки окна** — композитор не поддерживает `xdg-decoration` (например, GNOME).
Так задумано: окно без украшений. Перемещать его можно средствами композитора,
например `Super`+перетаскивание.

**Программа ругается на неизвестный терминал** — на удалённом сервере нет terminfo для
`xterm-256color`. Это редкость. Можно выставить `TERM=xterm` для этой сессии.

**Текст размыт на HiDPI-экране** — композитор не сообщает масштаб через
`preferred_buffer_scale` (`wl_compositor` ниже v6). Поддержка `wl_output.scale`
и дробного масштаба запланирована.

## 10. Для разработчиков

### Структура

```
Bixis/
├── Makefile            сборка всех компонентов
├── ROADMAP.md          планы
├── CHANGELOG.md        история версий
├── docs/MANUAL.md      это руководство
└── term/               bixis-term
    ├── config.h        настройки (suckless-стиль)
    ├── Makefile
    ├── src/
    │   ├── main.c      Wayland: окно, буферы, ввод, буфер обмена, вкладки, цикл poll()
    │   ├── term.c      эмулятор VT: парсер, экран, скроллбэк, PTY (без Wayland)
    │   ├── render.c    программная отрисовка в wl_shm, перерисовка только изменённых строк
    │   ├── font.c      fontconfig + FreeType, кэш глифов, fallback-шрифты
    │   └── util.h
    └── tests/vt.c      тесты эмулятора
```

### Как это устроено

- **Цикл событий** — один `poll()` по сокету Wayland, всем PTY, таймеру автоповтора
  и каналу вставки. Ни потоков, ни таймеров «на всякий случай».
- **Кадры** — рисуем только когда что-то изменилось и композитор готов (`wl_surface.frame`).
  Сколько бы данных ни пришло между кадрами, отрисовка будет одна.
- **Буферы** — два `wl_shm`-буфера. Для каждого хранится снимок ячеек, которые он показывает.
  Перерисовываются только строки, отличающиеся от снимка, и композитору отправляется
  damage только по ним.
- **Строки экрана** знают, сколько в них занятых ячеек (`ROW_USED`), поэтому прокрутка
  и запись в скроллбэк стоят O(длина текста), а не O(ширина окна).
- **Скроллбэк** — кольцевой буфер, строки хранятся без хвостовых пробелов.

Цифры на момент v0.1: бинарник около 100 КБ, RSS около 14 МБ с одной вкладкой,
парсер обрабатывает 100–125 МБ/с вывода на обычном тексте.

### Сборка для отладки и тесты

Тесты эмулятора с AddressSanitizer и UBSan:

```bash
make -C term check
```

Отладочная сборка:

```bash
make -C term clean all CFLAGS="-O0 -g -fsanitize=address,undefined" LDFLAGS="-fsanitize=address,undefined"
```

Протокольный лог Wayland:

```bash
WAYLAND_DEBUG=1 ./term/build/bixis-term
```

### Правила кода

- C11, стиль ядра Linux: табы, `snake_case`, фигурная скобка функции на новой строке.
- `term.c` не знает про Wayland, `render.c` — про PTY.
- Каждое изменение для пользователя записывается в [CHANGELOG](../CHANGELOG.md).

## 11. Удаление

```bash
sudo make uninstall
```

Если устанавливал с `PREFIX`, укажи его и здесь:

```bash
make uninstall PREFIX=$HOME/.local
```
